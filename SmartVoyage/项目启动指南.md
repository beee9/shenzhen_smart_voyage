# SmartVoyage 从零跑起来

一份按顺序照做就能跑通的指南：装中间件 → 建表灌数据（MySQL + Milvus）→ 起 MCP/A2A 服务 → 开 Streamlit 前端。

## 0. 整体结构

请求从上往下走，每一层都依赖下一层，所以启动顺序不能反：

```
Streamlit 前端        :8501
      ↓ HTTP
api_server.py         :8088   FastAPI，/api/chat 等接口
      ↓
chat_service.py               意图识别 → 分发给对应子代理
      ↓ A2A 协议
A2A 代理服务器        :5005 weather  :5006 ticket  :5007 trip
      ↓ MCP 协议 (streamable-http)
MCP 工具服务器        :8001 ticket   :8002 weather  :8003 trip
      ↓
MySQL :3306                   业务数据（9 张表）
Milvus :19530                 旅游团向量检索（tour_groups）
```

端口一览：

| 服务 | 端口 | 起法 |
|---|---|---|
| MySQL | 3306 | docker |
| Milvus | 19530 | docker |
| Attu（Milvus 可视化） | 8000 | docker |
| ticket MCP | 8001 | `python -m SmartVoyage.mcp_server.mcp_ticket_server` |
| weather MCP | 8002 | `python -m SmartVoyage.mcp_server.mcp_weather_server` |
| trip MCP | 8003 | `python -m SmartVoyage.mcp_server.mcp_trip_server` |
| weather A2A | 5005 | `python -m SmartVoyage.a2a_server.weather_server` |
| ticket A2A | 5006 | `python -m SmartVoyage.a2a_server.ticket_server` |
| trip A2A | 5007 | `python -m SmartVoyage.a2a_server.trip_server` |
| API 服务 | 8088 | `python -m SmartVoyage.api_server` |
| Streamlit | 8501 | `streamlit run SmartVoyage/streamlit_app.py` |

## 1. 前置准备

### 1.1 创建虚拟环境 lang_env

先建环境再装依赖，别装到全局 Python 里 —— 这个项目锁了几十个包的具体版本（`langchain`、`mcp`、`pymilvus` 这些版本之间是配套的），装全局迟早和别的项目互相顶掉。

项目用 Python 3.12。在仓库根目录（`shenzhen_smart_voyage/`）执行：

```bash
# 建环境（只需一次）
python -m venv lang_env
```

激活，按你的终端选一条：

```bash
# Windows CMD
lang_env\Scripts\activate.bat

# PowerShell
lang_env\Scripts\Activate.ps1

# Git Bash
source lang_env/Scripts/activate
```

激活成功后命令行提示符前面会出现 `(lang_env)`。确认一下用的是环境里的 Python：

```bash
python --version      # 应该是 3.12.x
where python          # 路径应指向 lang_env\Scripts\python.exe（Git Bash 用 which）
```

PowerShell 首次激活报「无法加载文件，因为在此系统上禁止运行脚本」，是执行策略挡的，放开当前用户即可：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

用 conda 的话换成这两条（效果一样，后面步骤都通用）：

```bash
conda create -n lang_env python=3.12 -y
conda activate lang_env
```

退出环境是 `deactivate`（conda 是 `conda deactivate`）。

⚠️ **后面所有命令都要在激活状态下跑** —— 建表、灌数据、起 6 个服务、起 API、起 Streamlit，每开一个新终端都要先激活一次。这是最容易漏的一步：新终端不会自动继承激活状态，忘了激活就会报 `ModuleNotFoundError`。

### 1.2 Python 依赖

确认 `(lang_env)` 已经在提示符里，然后在仓库根目录执行：

```bash
pip install -r requirements.txt
```

关键依赖及版本（已在 requirements.txt 里锁定）：`mysql-connector-python==9.4.0`、`pymilvus==3.0.1`、`mcp==1.18.0`、`python-a2a==0.5.4`、`langchain-mcp-adapters==0.1.11`、`fastapi==0.116.1`、`streamlit==1.47.1`。

### 1.3 大模型 API Key

`config.py` 从环境变量读 key，代码里没有写死：

```bash
# Windows CMD
set DASHSCOPE_API_KEY=sk-xxxxxxxx
# PowerShell
$env:DASHSCOPE_API_KEY="sk-xxxxxxxx"
# Git Bash
export DASHSCOPE_API_KEY=sk-xxxxxxxx
```

这个 key 有两处用到：对话模型（`qwen3.6-plus`）和 Embedding（`text-embedding-v3`，1024 维）。**灌 Milvus 数据前必须设好**，否则 `init_tour_group_rag.py` 拿不到向量。

注意 key 要设在**启动服务的那个终端**里。用 `main.py` 一键起服务时子进程会继承，单独开终端起服务的话每个终端都要设。

### 1.4 关掉本机 MySQL 服务

docker 里的 MySQL 要占 3306。本机装过 MySQL 的先停掉：

```bash
sc query | findstr -i mysql      # 查服务名
net stop MySQL57                 # 换成实际服务名，需要管理员权限
```

### 1.5 系统代理要绕开回环地址

开着 Clash / v2ray 这类代理（7890 端口）时，`httpx` 会把 `127.0.0.1` 的请求也发给代理，代理转发不了回环地址，直接返回 **502 Bad Gateway**。本机服务之间全是回环调用，所以这一步不能跳。

`main.py` 已经用 `os.environ.setdefault` 设了 `NO_PROXY`，`utils/http_client.py` 也设了 `trust_env=False`。但如果你不走 `main.py`、而是自己单独起服务，就要手动设：

```bash
set NO_PROXY=127.0.0.1,localhost
set no_proxy=127.0.0.1,localhost
```

大小写都设：`httpx` 只认小写，`requests` 两种都认（`python_a2a` 内部用的是 `requests`）。

服务之间报 502 或 Connection error 时，先怀疑这里。

## 2. 装 MySQL 和 Milvus（docker-compose 一把起）

所有中间件都在 `SmartVoyage/docker/docker-compose.yml` 里，不用单独装 MySQL 和 Milvus。

```bash
cd SmartVoyage/docker
docker compose up -d
```

也可以用绝对路径，不用先 cd：

```bash
docker compose -f D:\shenzhen_06\student\04-code\shenzhen_smart_voyage\SmartVoyage\docker\docker-compose.yml up -d
```

起来 6 个容器：

| 容器 | 镜像 | 端口 | 说明 |
|---|---|---|---|
| smart-mysql | mysql:5.7 | 3306 | 业务库 `travel_rag` |
| milvus-standalone | milvusdb/milvus:v2.4.4 | 19530 / 9091 | 向量库本体 |
| milvus-etcd | etcd:v3.5.5 | 内部 | Milvus 元数据 |
| milvus-minio | minio | 内部 | Milvus 对象存储 |
| milvus-attu | zilliz/attu:v2.4 | 8000 | 可视化界面 |

关于 Milvus 这套四件套：Milvus 本体不自己存元数据和文件，元数据交给 etcd、对象文件交给 MinIO，所以这三个必须一起起。etcd 和 MinIO 不暴露端口，Python 客户端碰不到也不用碰，compose 里的 `minioadmin` 账号是给 Milvus 内部用的。

确认状态：

```bash
docker compose ps                       # 6 个都应该是 Up
docker compose logs -f standalone       # Milvus 起得慢，等健康检查通过
curl http://localhost:9091/healthz      # 返回 OK 才算就绪
```

Milvus 首次启动要 1-2 分钟（compose 里 `start_period: 90s`）。急着往里灌数据会连不上，等 `healthz` 返回 OK 再往下走。

浏览器打开 <http://localhost:8000> 是 Attu，能看 collection、schema、数据，也能直接跑检索，调试的时候比写脚本快。

其他常用命令：

```bash
docker compose stop     # 停掉，数据保留
docker compose down     # 删容器，volumes/ 里的数据还在
```

数据落在 `docker/volumes/` 下（`mysql/`、`milvus/`、`etcd/`、`minio/`），`down` 不会删。真要清空重来，手动删这个目录。

### 账号说明

MySQL 有两个账号，用途不同，别混：

| 账号 | 密码 | 权限 | 谁在用 |
|---|---|---|---|
| root | 123456 | 全部，含建库删库 | `run_sql_file.py` 建表用 |
| smart_yoyage | 123456 | 仅 `travel_rag` 库内 | 应用运行时用（`config.py`） |

建表脚本第一句是 `DROP DATABASE`，属于库级操作，业务账号做不了会报 Access denied，所以建表必须用 root。

Milvus 2.x 默认 `authorizationEnabled=false`，不开认证，`connections.connect(host, port)` 直接连，不需要账号密码。

## 3. MySQL 建表 + 灌数据

脚本都在 `SmartVoyage/docker/data_init/`，**在仓库根目录执行**（要靠 `PYTHONPATH=.` 才能 import 到 `SmartVoyage.config`）。

### 3.1 一条龙：建表 + 灌数据

```bash
python SmartVoyage/docker/data_init/run_sql_file.py
```

默认按顺序跑两个 .sql，顺序不能反：

1. `create_all_tables.sql` — 建库 + 建 9 张表
2. `insert_may01_data.sql` — 灌五一假期的演示数据

⚠️ `create_all_tables.sql` 第一句是 `DROP DATABASE IF EXISTS travel_rag`，**整个库连数据一起删，不可恢复**。所以脚本默认会交互确认一次。非交互批跑加 `--yes` 跳过。

⚠️ 跑之前把应用停掉。应用连接池里挂着未提交的连接时，`DROP DATABASE` 会被元数据锁挡住，而本机等锁上限是一年 —— 表现出来就是「脚本卡住不动」。

9 张表：

| 表名 | 说明 |
|---|---|
| train_tickets | 火车票 |
| flight_tickets | 航班机票 |
| concert_tickets | 演唱会门票 |
| weather_data | 天气数据 |
| car_rentals | 租车信息 |
| insurances | 旅行保险 |
| user_profiles | 用户偏好 |
| query_history | 查询历史 |
| short_term_messages | 短期对话 |

前 6 张由 `insert_may01_data.sql` 灌演示数据，后 3 张是应用运行时自己写的，初始为空。

### 3.2 只灌数据，不动表结构

表已经建好、只想重灌或补数据时用这个。它不碰表结构，也不会删库，可以反复跑：

```bash
python SmartVoyage/docker/data_init/run_insert_data.py
```

三种模式：

```bash
# 默认 ignore：已存在的行自动跳过，重复跑安全
python SmartVoyage/docker/data_init/run_insert_data.py

# replace：同唯一键的旧行被新数据覆盖（改了价格、余票后重灌用这个）
python SmartVoyage/docker/data_init/run_insert_data.py --mode replace

# strict：原样 INSERT，撞唯一键报 1062
python SmartVoyage/docker/data_init/run_insert_data.py --mode strict
```

两个脚本的分工：`run_sql_file.py` 管 DDL（建库建表，用 root，破坏性）；`run_insert_data.py` 管 DML（只灌数据，用业务账号，幂等）。

脚本跑完会打印每张表的行数变化和抽查几条真实数据 —— 看到行数对得上、能查出内容，这一步才算成。如果输出「净增 0 行」且没有报错，说明数据本来就全在库里了，ignore 模式跳过了全部重复行，属正常。

## 4. Milvus 建 collection + 灌向量数据

```bash
python SmartVoyage/docker/data_init/init_tour_group_rag.py
```

这一条命令做四件事：

1. 连 Milvus（`localhost:19530`）
2. 建 `tour_groups` collection —— **已存在会先 drop 再重建**，开发阶段方便，生产上绝对不能这么干
3. 逐条调 DashScope Embedding API 把旅游团文本转成 1024 维向量，批量 insert 后 flush 落盘
4. 建向量索引 `IVF_FLAT` + `COSINE`（`nlist=64`）—— 索引必须建，不然检索极慢

旅游团数据直接写在脚本里的 `TOUR_GROUPS` 常量里（云南、西安等地的团），不从外部文件读。要加团就改这个列表再重跑。

Embedding 的输入是 `城市 + 团名 + 亮点` 拼起来的一段文本，所以用户问「有雪山能看日出的地方」这种自然语言也能命中。

collection 字段：`tour_id`、`tour_name`、`city`、`days`、`price`、`total_seats`、`remaining_seats`、`agency`、`rating`、`departure_dates`（JSON 字符串）、`highlights`、`embedding`(1024 维)，主键 `id` 自增。

### 验证检索效果

加 `--test` 会跑 5 条语义搜索测试，打印每条查询命中的团和相似度距离：

```bash
python SmartVoyage/docker/data_init/init_tour_group_rag.py --test
```

不加 `--test` 就跳过，省 5 次 Embedding API 调用。

也可以打开 Attu <http://localhost:8000> 直接看 `tour_groups` 有没有数据、索引建没建上。

⚠️ 这一步依赖 `DASHSCOPE_API_KEY`。没设的话向量拿不到，脚本会在 embedding 环节报错，而 collection 已经建好了 —— 表现出来就是「有表没数据」。设好 key 重跑一次即可（反正会 drop 重建）。

## 5. 起 MCP 和 A2A 服务

6 个服务，启动顺序有讲究：**先 MCP 再 A2A**。A2A 代理启动时要连 MCP 拉工具列表（`load_mcp_tools`），MCP 没起来它就拿不到工具。

### 5.1 推荐：一键起全部（顺带一个 CLI）

```bash
python -m SmartVoyage.main
```

`main.py` 会按顺序把 6 个服务拉成子进程，逐个等端口就绪，然后进一个命令行对话循环。它还顺手做了几件省事的事：

- **端口已占用就跳过**，重复执行不会撞端口，也不会误关你已经起好的服务
- 日志按服务分文件写到 `SmartVoyage/logs/`，6 个进程的输出不糊在一个终端里
- 自动设 `NO_PROXY`，子进程继承，绕开 1.5 节那个 502 坑
- 退出时统一回收自己拉起的子进程（启动前就在跑的不动）

输出里每个服务应该是 `[就绪]` 或 `[跳过]`。出现 `[警告] xxx 启动超时`，去 `logs/` 下看对应的 `.log`。

注意：`main.py` 只起这 6 个服务，**不起 api_server 和 Streamlit**。要用网页版，api_server 得另开终端（见第 6 节）。

### 5.2 手动逐个起（调试用）

想看某个服务的实时输出时，一个终端一个：

```bash
# 先起 3 个 MCP 工具服务器
python -m SmartVoyage.mcp_server.mcp_ticket_server     # 8001
python -m SmartVoyage.mcp_server.mcp_weather_server    # 8002
python -m SmartVoyage.mcp_server.mcp_trip_server       # 8003

# 等上面 3 个都起来了，再起 3 个 A2A 代理服务器
python -m SmartVoyage.a2a_server.weather_server        # 5005
python -m SmartVoyage.a2a_server.ticket_server         # 5006
python -m SmartVoyage.a2a_server.trip_server           # 5007
```

MCP 走 `streamable-http`，端点是 `/mcp`（比如 <http://127.0.0.1:8002/mcp>）。A2A 用 `python_a2a` 的 `run_server`，都只监听 `127.0.0.1`，不对局域网开放 —— 这些工具没有认证，别改成 `0.0.0.0`。

对应关系：

| A2A 代理 | 端口 | 连的 MCP |
|---|---|---|
| WeatherQueryAssistant | 5005 | 8002 weather |
| TicketAssistant | 5006 | 8001 ticket |
| TripAssistant | 5007 | 8003 trip |

意图到代理的映射在 `config.py` 的 `intent` 里：`weather` → 天气；`flight`/`train`/`concert`/`order` → 票务；`car_rental`/`tour_group`/`insurance`/`trip_order` → 行程。

## 6. 起 API 服务和 Streamlit 前端

前端不直连 A2A，它只认 `http://127.0.0.1:8088` 这一个地址（`streamlit_app.py` 里的 `API_BASE`），所以 api_server 必须先起。

### 6.1 API 服务（终端 A）

```bash
PYTHONPATH=. python -m SmartVoyage.api_server
```

FastAPI 跑在 `127.0.0.1:8088`。接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/chat` | 一次性返回 |
| POST | `/api/chat/stream` | 流式返回 |
| GET | `/api/memory` | 读记忆 |
| POST | `/api/memory/profile` | 写用户偏好 |
| POST | `/api/memory/clear` | 清记忆 |
| GET | `/api/agents` | 子代理状态 |

自带文档：<http://127.0.0.1:8088/docs>

### 6.2 Streamlit 前端（终端 B）

在仓库根目录：

```bash
streamlit run SmartVoyage/streamlit_app.py
```

浏览器会自动打开 <http://localhost:8501>。要换端口：

```bash
streamlit run SmartVoyage/streamlit_app.py --server.port 8502
```

前端有连通性自检，连不上 8088 会直接显示 `连不上 http://127.0.0.1:8088`，不会卡在转圈。看到这个提示就回去看 api_server 那个终端。

### 6.3 完整启动顺序汇总

冷启动一共四步，三个终端。**每个终端第一件事都是激活 lang_env**：

```bash
# 0) 中间件（只需一次，之后 docker 自己 restart）
cd SmartVoyage/docker && docker compose up -d

# 0.5) 建表灌数据（只需一次）
source lang_env/Scripts/activate
PYTHONPATH=. python SmartVoyage/docker/data_init/run_sql_file.py
PYTHONPATH=. python SmartVoyage/docker/data_init/init_tour_group_rag.py

# 1) 终端 A：6 个后端服务
source lang_env/Scripts/activate
python -m SmartVoyage.main

# 2) 终端 B：API 服务
source lang_env/Scripts/activate
python -m SmartVoyage.api_server

# 3) 终端 C：前端
source lang_env/Scripts/activate
streamlit run SmartVoyage/streamlit_app.py
```

上面用的是 Git Bash 的激活写法，CMD 换成 `lang_env\Scripts\activate.bat`，PowerShell 换成 `lang_env\Scripts\Activate.ps1`。

日常重启只需要 1-3 步，数据和容器都在。

## 7. 踩坑排查

### ModuleNotFoundError

两种原因，先看提示符里有没有 `(lang_env)`：

- 没有 → 忘了激活虚拟环境。新开的终端不继承激活状态，每个终端都得来一次（见 1.1）。
- 有 → 缺 `PYTHONPATH=.`，或者不在仓库根目录。报的是 `No module named 'SmartVoyage'` 基本就是这个。

### 服务之间报 502 / Connection error

本机代理（Clash 7890 那类）把回环请求也劫走了。见 1.5 节，设 `NO_PROXY=127.0.0.1,localhost`（大小写都设）。这是最常见的一个，本机服务全是回环调用，一开代理就全线崩。

### 查天气返回 no_data

`weather_data` 表里存的城市名是**区级粒度** —— 是「深圳宝安」而不是「深圳」。用「深圳」查匹配不上，返回 no_data 是数据粒度问题，不是代码坏了。

顺带一提，`config.py` 里 `weather_source` 默认是 `"api"`，走和风天气实时接口，不读库。改成 `"database"` 才查 `weather_data` 表，那时候才会碰到上面这个坑。

### 数据库连接失败

按顺序查：容器起了没（`docker compose ps`）→ 3306 是不是被本机 MySQL 占了（见 1.4）→ 账号密码对不对（见第 2 节账号表）。

有个容易踩的点：`config.py` 里那个 `get_mysql_config(env)` 方法返回的是 `root/root`，和实际能用的账号都对不上，但**它在应用代码里从没被调用过**，只在 `config.py` 自己的 `__main__` 里打印。真正生效的是 `__init__` 里的 `smart_yoyage/123456`。改数据库配置要改 `__init__`，改那个方法没有任何效果。

### Milvus 连不上 / 集合不存在

Milvus 首次启动要 1-2 分钟，`curl http://localhost:9091/healthz` 返回 OK 才算好。报「集合 tour_groups 不存在」就是第 4 节没跑，跑一遍 `init_tour_group_rag.py`。

### A2A 拿不到工具 / 启动超时

八成是 MCP 没先起来。确认 8001/8002/8003 在监听，再起 5005/5006/5007。`main.py` 已经处理了顺序，手动起的时候容易搞反。

### 端口被占

`main.py` 遇到端口占用会打 `[跳过]` 而不是报错 —— 如果你改了代码却发现行为没变，可能连的是上一次残留的旧进程。查一下：

```bash
netstat -ano | findstr "8001 8002 8003 5005 5006 5007 8088"
taskkill /PID <pid> /F
```

### 看链路日志

`main.py` 的 CLI 里敲 `trace`，会回放最近一次请求走过的每一层。子代理和 MCP 侧的详细日志在 `SmartVoyage/logs/` 下对应服务的 `.log` 文件里。
