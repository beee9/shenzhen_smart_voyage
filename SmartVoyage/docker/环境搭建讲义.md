# SmartVoyage 环境搭建讲义（Windows）

配套文件：`SmartVoyage/docker/docker-compose.yml`、`SmartVoyage/docker/data_init/`
参考文档：`SmartVoyage/docker/docker环境说明.md`

命令统一在 **PowerShell** 里执行。

## 学习目标

跟完这份讲义，你应该能做到：

1. 说清 SmartVoyage 依赖哪些中间件、各自解决什么问题、谁依赖谁
2. 用一条命令把这套中间件跑起来
3. 把表建好、数据灌好、向量库初始化好
4. 分四层验证环境是否真的可用，而不是"容器 Up 了就以为好了"
5. 遇到起不来时，知道先看什么、再看什么

主线只有一条命令：`docker compose up -d`。前面的准备和后面的验证才是重点。

## 一、先看清要搭什么

### 1 为什么用 Docker

SmartVoyage 要用到 MySQL、Milvus 向量库、以及 Milvus 自己依赖的 etcd 和 MinIO。
四种中间件、四套安装方式、四套配置文件，手工装一遍很容易版本对不齐，
结果就是"老师能跑我不能跑"。

容器化之后这些差异被镜像吃掉了：**拉的是同一份镜像，跑的是同一套配置**。
你要负责的只有两件事 —— 装好 Docker，把宿主机的端口和目录让出来。

### 2 服务清单

| 服务名 | 容器名 | 宿主机端口 | 用途 | 你会直接打交道吗 |
|---|---|---|---|---|
| `mysql` | `smart-mysql` | **3306** | 业务库 `travel_rag`，9 张表 | ✅ 代码连它 |
| `standalone` | `milvus-standalone` | **19530** / 9091 | Milvus 向量库，`tour_groups` collection | ✅ 代码连它 |
| `attu` | `milvus-attu` | **8000** | Milvus 可视化界面 → http://localhost:8000 | ✅ 浏览器看 |
| `etcd` | `milvus-etcd` | 不暴露 | Milvus 的元数据存储 | ❌ 只要活着 |
| `minio` | `milvus-minio` | 不暴露 | Milvus 的对象存储 | ❌ 只要活着 |

注意后两个：**不暴露端口，但必须跟着起**。Milvus 把 collection 的 schema、
分区信息这类元数据写进 etcd，把真正的向量文件写进 MinIO。少一个 Milvus 就起不来 ——
课上最常见的现象是"standalone 容器反复重启"，八成是 etcd 或 minio 没活。

依赖关系一句话：`attu → standalone → (etcd + minio)`，`mysql` 独立。
compose 里的 `depends_on` 已经写好这个顺序，不用手工控制启动次序。

### 3 已知的文档与实际不一致（照抄前先看这里）

现有 `docker环境说明.md` 有三处和仓库现状不符，照着做会踩空：

| 说法 | 实际 | 怎么办 |
|---|---|---|
| 服务清单里有 `redis` 6379，密码 `1234` | `docker-compose.yml` 里**没有 redis 服务**，代码里也没有任何 redis 调用 | 忽略 redis，不影响任何功能 |
| `cd "D:\...\prepare_smart_voyage\docker"` | 实际路径是 `prepare_smart_voyage\SmartVoyage\docker`，少了一层 | 用本讲义第五节的路径 |
| 挂载目录 `docker/mysql-init/` | 目录下还有一个空的 `mysql_init/`（下划线），没人用 | 放 `.sql` 只能放**横杠**那个 |

`启动脚本` 那个文件里的路径同样少了 `SmartVoyage` 一层，别直接复制。

## 二、装 Docker Desktop

### 1 前置：开启 WSL2

Docker Desktop 在 Windows 上底层是用 WSL2 跑一个 Linux 虚拟机，所以先把 WSL2 装好。
管理员身份打开 PowerShell：

```powershell
# 装 WSL（装完要重启电脑）
wsl --install

# 重启后确认 VERSION 是 2
wsl -l -v
```

另外确认 BIOS 里的虚拟化（Intel VT-x / AMD-V）是开着的。这一项默认多半是开的，
但如果 Docker Desktop 启动时报虚拟化相关的错，就要进 BIOS 检查。

### 2 装 Docker Desktop

官网下载 Docker Desktop for Windows 安装包，一路下一步。安装时勾选
"Use WSL 2 instead of Hyper-V"（默认就是）。

⚠️ 装完之后 **Docker Desktop 必须一直开着**，托盘图标显示运行状态才行。
关掉它，所有容器都会停。这是 Windows 上最常见的"昨天还好今天连不上"。
建议在 Settings → General 里勾上 **Start Docker Desktop when you sign in**。

### 3 验证

```powershell
docker --version          # 有版本号就说明装上了
docker compose version    # 注意是空格，不是 docker-compose
docker run --rm hello-world    # 能拉能跑，说明引擎和网络都通
```

`docker-compose`（带横杠）是 v1 的老命令，现在是插件形式的 `docker compose`（空格）。
新版 Docker 里横杠版可能根本不存在，本讲义统一用**空格版**。

`hello-world` 拉不下来是网络问题，不是你操作错了 —— 往下走第三节。

## 三、配镜像加速

Milvus 镜像有几百 MB，不配加速基本拉不动。卡在 `Retrying in N seconds` 就是这个原因。

### 1 在图形界面里改

不要去找配置文件，Docker Desktop 里直接改：**Settings → Docker Engine**，
在右边的 JSON 里加上 `registry-mirrors`：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.mirrors.ustc.edu.cn",
    "https://mirror.baidubce.com"
  ]
}
```

改完点 **Apply & Restart**，等 Docker 重启完。

⚠️ 这是严格 JSON，**最后一项后面不能有逗号**。多一个逗号，Docker 会拒绝保存
或静默用回旧配置。这是抄现成配置最常踩的坑 —— 网上流传的那些镜像源清单，
很多末尾都带着多余的逗号。

### 2 验证是否真的生效

```powershell
docker info | Select-String -Pattern "Registry Mirrors" -Context 0,3
```

能看到你填的地址才算成功。**这一步别省** —— 光改了没重启是不生效的，
看不到生效就继续往下走，会浪费十几分钟在"为什么还是拉不动"。

镜像源失效是常态。上面三个都不通就换：`https://docker.1panel.live`、
`https://dockerpull.org`、`https://hub.rat.dev`、`https://docker.nju.edu.cn`。
换完记得重新验证一次。

## 四、⚠️ 启动前必须腾出 3306 端口

compose 里 MySQL 映射的是 `3306:3306`。你机器上要是装过 MySQL 服务，
它占着 3306，**容器会起不来并反复重启**。这是全场最高频的失败原因，先处理它。

### 1 先看端口占没占

```powershell
netstat -ano | findstr :3306
```

没有任何输出，说明端口空着，跳到第 3 小节。

### 2 停掉本机 MySQL

```powershell
# 先查服务名
sc query | findstr -i mysql

# 再停（服务名按上一步查到的填，常见 MySQL57 / MySQL80 / MySQL）
net stop MySQL57
```

`net stop` 报权限错误，就用管理员身份重开 PowerShell。

### 3 不想停本机 MySQL？改容器端口

两个 MySQL 并存也可以，但要改**三个地方**，少一个就连不上：

```yaml
# ① docker-compose.yml
mysql:
  ports:
    - "3307:3306"        # 宿主机 3307 → 容器内仍是 3306
```

```python
# ② SmartVoyage/config.py，加一行
self.port = 3307
```

③ 所有 `mysql.connector.connect(...)` 调用处补上 `port=conf.port`。目前有 6 处：

- `SmartVoyage/chat_service.py:52`
- `SmartVoyage/mcp_server/mcp_ticket_server.py:16`
- `SmartVoyage/mcp_server/mcp_trip_server.py:81`
- `SmartVoyage/mcp_server/mcp_weather_server.py:16`
- `SmartVoyage/docker/data_init/run_sql_file.py:282`
- `SmartVoyage/docker/data_init/run_insert_data.py:195`

这些调用现在都没传 `port`，走的是默认 3306。**六处改不全，就会出现"有的功能好有的坏"**
—— 比全挂掉更难查。课上建议直接停本机 MySQL，改端口留作课后练习。

### 4 顺带检查其它三个端口

`19530`（Milvus）、`8000`（Attu）、`9091`（Milvus metrics）也要空着：

```powershell
netstat -ano | findstr "19530 8000 9091"
```

8000 比较容易被别的开发服务占用。Attu 的端口冲突最好解决，改 compose 里
`"8000:3000"` 左边那个数字即可（比如改成 `"8010:3000"`，然后访问 http://localhost:8010）。
它只是个界面，不被任何代码引用，改了不用同步别处。

## 五、Python 环境

中间件在容器里，但**业务代码跑在宿主机上**，Python 环境还是要自己装。

### 1 建环境

```powershell
conda create -n smart_voyage python=3.12 -y
conda activate smart_voyage
```

PyCharm 里注意解释器要选到这个环境。

### 2 装依赖

```powershell
cd "D:\我的备课\prepare_smart_voyage"
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

`requirements.txt` 是全量 pin 版本的环境快照，里面包含 `torch 2.7.1` 这种大包
（几百 MB，为后续课程准备），装的时候耐心等。一定要加 `-i` 换国内源，否则会超时。

关键包对照：

| 包 | 版本 | 谁在用 |
|---|---|---|
| `mysql-connector-python` | 9.4.0 | 所有 MySQL 访问 |
| `pymilvus` | 3.0.1 | Milvus 向量检索 |
| `streamlit` | 1.47.1 | 前端界面 |
| `fastapi` + `uvicorn` | 0.116.1 / 0.35.0 | `api_server.py` |
| `mcp` | 1.18.0 | MCP 服务 |
| `python-a2a` | 0.5.4 | A2A 服务 |

### 3 配 API Key

`config.py` 从环境变量读 DashScope 的 key，**不要硬编码进代码**：

```powershell
setx DASHSCOPE_API_KEY "sk-你的key"
```

⚠️ `setx` 写的是永久变量，但**当前这个终端读不到**，必须重开 PowerShell 才生效。
不重开就往下走，会看到一个很迷惑的"key 明明设了却说没设"。

验证：

```powershell
python -c "import os; print('OK' if os.getenv('DASHSCOPE_API_KEY') else '没读到')"
```

这个 key 有两处用途 —— 对话模型（`qwen3.6-plus`）和 embedding（`text-embedding-v3`）。
第六节初始化向量库时会真实调用 embedding 接口，**会消耗额度**，所以那一步别反复跑。

## 六、启动中间件与灌数据

### 1 启动

必须先 `cd` 进 `docker/` 目录 —— compose 里的挂载路径写的是相对路径
（`./volumes/mysql`），在别的目录跑会把数据卷建到错误的地方。

```powershell
cd "D:\我的备课\prepare_smart_voyage\SmartVoyage\docker"
docker compose up -d
```

`-d` 是后台运行。不加 `-d` 日志会糊满终端，而且 Ctrl+C 会把容器停掉。

首次启动要拉五个镜像，约 1–2 GB。之后再启动只要十几秒。

### 2 看状态

```powershell
docker compose ps
```

期望所有服务都是 `Up`，带 healthcheck 的显示 `(healthy)`。

⚠️ **Milvus 就绪要 30–60 秒**，比容器变成 `Up` 晚得多。它得等 etcd 和 MinIO 先健康，
再自己加载元数据。`up -d` 一返回就立刻跑 Python 连 19530，大概率报连接失败 ——
这不是配置错，是等得不够久。compose 里给 standalone 设了 `start_period: 90s`
就是这个道理。

想看清它在干什么：

```powershell
docker compose logs -f standalone     # Ctrl+C 只是退出看日志，不会停容器
```

### 3 常用命令

| 命令 | 作用 | 数据会丢吗 |
|---|---|---|
| `docker compose up -d` | 创建并启动 | — |
| `docker compose ps` | 看状态 | — |
| `docker compose stop` | 停止，容器保留 | ❌ 不丢 |
| `docker compose start` | 再启动 | ❌ 不丢 |
| `docker compose restart` | 重启 | ❌ 不丢 |
| `docker compose down` | 删容器 | ❌ 不丢（数据在 `volumes/`） |
| `docker compose logs <服务名>` | 看某个服务日志 | — |
| 手工删 `volumes\` 目录 | 彻底清空 | ⚠️ **全丢** |

`down` 和删 `volumes\` 的区别要讲清：`down` 只删容器这个"运行实例"，
数据落在宿主机的 `docker\volumes\{mysql,milvus,etcd,minio}\` 下，重新 `up` 数据还在。
只有手工删掉那个目录，才是真的从零开始。

### 4 建表 + 灌 MySQL 数据

容器起来了不等于能用。MySQL 里现在只有一个**空库** `travel_rag`
（`MYSQL_DATABASE` 只负责建库，不建表）。仓库里已经备好了脚本，不用手写 SQL。
**在仓库根目录**执行：

```powershell
cd "D:\我的备课\prepare_smart_voyage"
$env:PYTHONPATH="."
python SmartVoyage\docker\data_init\run_sql_file.py
```

它按顺序跑两个文件，顺序不能反：

| 文件 | 干什么 | 用哪个账号 |
|---|---|---|
| `create_all_tables.sql` | 建库 + 建 9 张表 | `root` / `123456` |
| `insert_may01_data.sql` | 灌 5 月 1 日假期的演示数据 | 同上 |

⚠️ `create_all_tables.sql` **第一句是 `DROP DATABASE IF EXISTS travel_rag`**，
会把整个库连数据一起删掉且不可恢复。所以脚本默认要交互确认，看到提示再回车。
非交互批跑才用 `--yes` 跳过。

为什么用 root 而不是 `config.py` 里的 `smart_yoyage`：`DROP DATABASE` / `CREATE DATABASE`
是库级操作，业务账号只有库内权限，会报 `Access denied`。

⚠️ 跑之前**把业务应用停掉**。应用连接池里挂着未提交的连接时，`DROP DATABASE`
会被 MySQL 的元数据锁挡住，而等锁上限极长，表现出来就是"脚本卡住不动"，
看着像死机，其实是在排队。

### 5 只想补数据、不动表结构

表已经建好、只是想重新灌数据，用另一个脚本 —— 它不碰表结构，可以反复跑：

```powershell
python SmartVoyage\docker\data_init\run_insert_data.py
```

三种模式的区别是课上的一个小考点：

| `--mode` | 撞唯一键时 | 什么时候用 |
|---|---|---|
| `ignore`（默认） | 跳过已存在的行 | 重复跑最安全 |
| `replace` | 用新数据覆盖旧行 | 改了价格、余票后重灌 |
| `strict` | 直接报 1062 错误 | 演示"为什么需要前两种" |

### 6 初始化 Milvus 向量库

```powershell
python SmartVoyage\docker\data_init\init_tour_group_rag.py
```

这个脚本做四件事：定义旅游团数据 → 调 DashScope embedding 把行程亮点转成 1024 维向量
→ 在 Milvus 建 `tour_groups` collection → 插入数据并建索引。

⚠️ **它会真实调用 embedding 接口，消耗 API 额度**，跑一次就够，别反复跑。
跑之前确认两件事：Milvus 已经 healthy（本节第 2 小节），`DASHSCOPE_API_KEY` 已设好。

### 7 另一种方式：让容器自动建表

把 `.sql` 文件放进 `docker\mysql-init\`（**横杠**那个目录，不是 `mysql_init\`），
容器**首次**启动时会按文件名顺序自动执行 —— 这是 MySQL 镜像的
`/docker-entrypoint-initdb.d` 机制。

"首次"两个字是重点：**这个目录只在数据卷为空时生效**。已经启动过再放文件不会执行，
得先 `docker compose down`，删掉 `volumes\mysql\`，再重新 `up`。

课上用脚本方式（第 4 小节）而不用这个，是因为脚本会打印每条语句的执行情况和最终行数，
出错能看见断在哪一条；自动初始化失败只会静默留下一个空库。

## 七、四层验证

不要跑完 `up -d` 就宣布搭好了。按下面四层依次验证，**每层通过再进下一层** ——
这样出问题时你能立刻知道断在哪一环，而不是面对一个笼统的"处理失败"。

### 第 1 层：容器活着

```powershell
docker compose ps
```

五个服务全 `Up`，`mysql` 和 `standalone` 带 `(healthy)`。

### 第 2 层：中间件能连上

MySQL：

```powershell
docker exec -it smart-mysql mysql -usmart_yoyage -p123456 -e "USE travel_rag; SHOW TABLES;"
```

期望看到 9 张表：`car_rentals`、`concert_tickets`、`flight_tickets`、`insurances`、
`query_history`、`short_term_messages`、`train_tickets`、`user_profiles`、`weather_data`。

Milvus 用浏览器验证最直观 —— 打开 **http://localhost:8000**（Attu），
连接地址填 `standalone:19530`，通常已经通过 `MILVUS_URL` 预填好，直接点连接。
连上后确认 `tour_groups` collection 存在、有数据、索引已建好。

⚠️ Attu 里**不能填 `localhost:19530`**。Attu 自己在容器里，`localhost` 指的是 Attu 容器自身。
容器之间通信要用**服务名**，Docker 内置 DNS 会把 `standalone` 解析到 Milvus 容器的内网 IP。
同理 compose 里 Milvus 连 etcd 写的是 `etcd:2379`。

而你的 Python 代码跑在**宿主机**上，所以 `config.py` 里写 `localhost:19530` 是对的 ——
走的是端口映射。**同一个 Milvus，两种地址，取决于你从哪里连**。这个区别值得课上单独强调。

### 第 3 层：Python 能连上

```powershell
python SmartVoyage\config.py
```

先确认配置本身能加载。然后分别验证两个库：

```powershell
# MySQL
python -c "import mysql.connector; from SmartVoyage.config import Config; c=Config(); conn=mysql.connector.connect(host=c.host,user=c.user,password=c.password,database=c.database); cur=conn.cursor(); cur.execute('SHOW TABLES'); print('MySQL OK，表数：', len(cur.fetchall()))"

# Milvus
python -c "from pymilvus import connections, utility; from SmartVoyage.config import Config; c=Config(); connections.connect(host=c.milvus_host,port=c.milvus_port); print('Milvus OK，collections：', utility.list_collections())"
```

这一层专门用来分离"中间件的问题"和"代码配置的问题"。第 2 层通过、第 3 层失败，
问题一定在 `config.py` 或 Python 依赖上，不用再折腾容器。

### 第 4 层：跑测试

仓库里有分层的测试，按依赖从轻到重：

| 测试文件 | 要先起 MCP 服务吗 | 测什么 |
|---|---|---|
| `tests\test_mcp_servers.py` | ❌ 直接调函数 | MCP 工具的业务逻辑 |
| `tests\test_agent_cards.py` | ❌ | AgentCard 定义 |
| `tests\test_agent_servers.py` | ✅ 跨进程 | A2A Server 的 HTTP 接口 |
| `tests\check_api_server.py` | ✅ 要起 `api_server.py` | 对外 API |

判断标准是一句话：**要不要起服务，看跨不跨进程**。同进程内直接 import 调函数的不用起；
走 HTTP 打到另一个进程的必须先起。

```powershell
python -m unittest SmartVoyage\tests\test_mcp_servers.py -v
```

详细说明见 `SmartVoyage\tests\为什么不用启动MCP服务就能测.md` 和
`SmartVoyage\tests\Agent层测试为什么必须先起MCP服务.md`。

## 八、配置对应关系与认证

### 1 compose 与 config.py 一一对应

`SmartVoyage/config.py` 是唯一的配置入口。它和 compose 的对应关系：

| `config.py` | compose 里的来源 |
|---|---|
| `self.host = 'localhost'` | mysql 的 `3306:3306` 端口映射 |
| `self.user = 'smart_yoyage'` | `MYSQL_USER` |
| `self.password = '123456'` | `MYSQL_PASSWORD` |
| `self.database = 'travel_rag'` | `MYSQL_DATABASE` |
| `self.milvus_host = 'localhost'` | standalone 的 `19530:19530` 端口映射 |
| `self.milvus_port = 19530` | 同上 |

改了 compose 里的用户名、密码、库名、端口，**必须同步改 `config.py`**，反之亦然。
两处不一致是最常见的"明明启动了却连不上"。

### 2 Milvus 不需要用户名密码

这一点容易让人以为漏配了什么。Milvus 2.x 默认 `authorizationEnabled=false`，
`connections.connect(host="localhost", port=19530)` 直接就能连，没有账号概念。
跟 MySQL 完全不同。

compose 里出现的凭据，只有 MySQL 那两组跟你有关：

| 凭据 | 属于谁 | 谁在用 |
|---|---|---|
| `smart_yoyage` / `123456` | MySQL | ✅ `config.py` 里的业务连接 |
| `root` / `123456` | MySQL | ✅ 只有建表脚本用 |
| `minioadmin` / `minioadmin` | MinIO | ❌ Milvus 内部访问对象存储 |
| （无） | Milvus | ❌ 不需要 |

### 3 ⚠️ 改了配置要重启对应服务

MCP 服务、A2A 服务是**长驻进程**，启动时读一次 `Config()` 就留在内存里。
改完 `config.py` 不重启，老进程用的还是旧配置 —— 报错会指向一个你以为早已修好的问题，
特别容易让人怀疑自己改错了地方。

**顺序是：改配置 → 重启服务 → 再验证。**

服务端口一览，方便你知道该重启哪个：

| 服务 | 端口 | 启动方式 |
|---|---|---|
| MCP 天气 | 8002 | `python SmartVoyage\mcp_server\mcp_weather_server.py` |
| MCP 票务 | 8001 | `python SmartVoyage\mcp_server\mcp_ticket_server.py` |
| MCP 行程 | 8003 | `python SmartVoyage\mcp_server\mcp_trip_server.py` |
| A2A 天气 | 5005 | `python SmartVoyage\a2a_server\weather_server.py` |
| A2A 票务 | 5006 | `python SmartVoyage\a2a_server\ticket_server.py` |
| A2A 行程 | 5007 | `python SmartVoyage\a2a_server\trip_server.py` |
| 对外 API | 8088 | `python SmartVoyage\api_server.py` |
| Streamlit 界面 | 8501 | `streamlit run SmartVoyage\streamlit_app.py` |

这些都是宿主机进程，**不在容器里**。本讲义只负责把中间件（3306 / 19530 / 8000）搭好，
上面这些服务怎么起、谁依赖谁，是后面课程的内容。

## 九、排查

排查的第一原则：**别猜，先看日志**。`docker compose logs <服务名>` 比猜快得多。

### 1 容器与中间件

| 现象 | 原因 | 处理 |
|---|---|---|
| `mysql` 容器反复重启 | 3306 被本机 MySQL 占用 | 见第四节，停掉本机服务 |
| `Fail connecting to server on localhost:19530` | Milvus 没起或还没就绪 | `docker compose ps` 看 standalone；**等满 60 秒** |
| `standalone` 起不来 | etcd 或 minio 挂了 | `docker compose logs etcd minio` |
| `Access denied for user 'smart_yoyage'` | 旧数据卷里没建这个用户 | `down` 后删 `volumes\mysql\` 重新 `up` |
| Attu 连不上 | 填了 `localhost:19530` | 改成 `standalone:19530` |
| `Exited (255)` | 宿主机或 Docker 重启导致 | `docker compose up -d` 重新拉起 |
| 拉镜像卡住 / `Retrying in N seconds` | 没配镜像加速 | 见第三节，配完**验证**再重试 |
| 中文乱码 | 字符集不是 utf8mb4 | 导入导出都加 `--default-character-set=utf8mb4` |

### 2 Docker Desktop 本身

| 现象 | 原因 | 处理 |
|---|---|---|
| `docker: command not found` | Docker Desktop 没开 | 开 Docker Desktop，等托盘图标变运行态 |
| `WSL 2 is not installed` | 缺 WSL2 | 管理员 PowerShell `wsl --install`，重启 |
| 容器莫名全停 | 关了 Docker Desktop | 它必须一直开着，建议设开机自启 |
| `docker compose` 找不到 | 用了横杠版的习惯 | 新版是空格版 `docker compose` |
| 虚拟化相关报错 | BIOS 没开 VT-x / AMD-V | 进 BIOS 开启虚拟化 |

### 3 Python 侧

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: No module named 'SmartVoyage'` | 没设 PYTHONPATH | 在仓库根目录跑，先 `$env:PYTHONPATH="."` |
| key 明明设了却读不到 | `setx` 对当前终端不生效 | 重开 PowerShell |
| 脚本卡在 `DROP DATABASE` 不动 | 业务应用占着连接，元数据锁排队 | 停掉所有业务进程再跑 |
| `net stop` 权限不足 | 不是管理员 | 管理员身份重开 PowerShell |
| 路径相关报错 | 中文路径没加引号 | 路径整体用双引号包住 |

### 4 核弹级重来

前面都试过还是不行，从零来一遍（⚠️ **数据全丢**）：

```powershell
cd "D:\我的备课\prepare_smart_voyage\SmartVoyage\docker"
docker compose down
Remove-Item -Recurse -Force volumes    # 慎重
docker compose up -d
# 然后重跑第六节第 4、6 小节的灌数据
```

删 `volumes\` 之前想清楚：MySQL 里的表和数据、Milvus 里的向量都会没，
第六节要整个重跑一遍，**包括那个会消耗 API 额度的 embedding 脚本**。
所以这是最后手段，不是"先试试看"。
